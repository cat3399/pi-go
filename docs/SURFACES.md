# Surface 架构

终端、Web 和桌面入口运行同一套 Go Core；Android 连接远程 Core。
GUI、Web 和移动端共用 `surface/ui` 的 React Workbench。

## 入口与通信

| 入口 | 通信方式 | Core 所在位置 |
|---|---|---|
| CLI `run` | 同进程 Runtime 调用 | 本机进程 |
| TUI | 同进程 typed Application API | 本机进程 |
| 桌面 GUI 本地模式 | Wails IPC → Application API | 桌面进程 |
| 桌面 GUI 远程模式 | HTTP/SSE | 远程 Web 服务 |
| 浏览器 Web UI | 当前 origin 的 HTTP/SSE | Web 服务 |
| Android | Go 网络桥接的 HTTP/SSE | 远程 Web 服务 |
| JSONL RPC | stdin/stdout → ApplicationSession | RPC 进程 |

Workbench 的 `ApplicationClient` 提供本地 IPC 和远程 HTTP/SSE 两种实现。
宿主负责窗口、导航、输入与连接适配；共享 UI 管理会话展示、项目选择、工具详情、文件预览和草稿。
状态所有权见[核心架构](ARCHITECTURE.md)。

## Application API 与 Web 协议

`internal/application.API` 提供 command、query、snapshot、项目目录、会话生命周期和应用级事件。
`application.Service` 管理多个独立的 ApplicationSession；各会话拥有自己的 Runtime。
`internal/protocol/v1` 为实际的协议消费者提供字段映射。

`surface/web` 的 HTTP 边界位于 `/api/v1`，主要端点包括：

| 方法和路径 | 用途 |
|---|---|
| `POST /api/v1/sessions` | 创建会话 |
| `GET /api/v1/snapshot` | 应用快照 |
| `GET /api/v1/sessions/{id}` | 单会话 durable/live 快照 |
| `POST /api/v1/sessions/{id}/commands` | 会话命令 |
| `POST /api/v1/projects` | 添加已有项目目录 |
| `DELETE /api/v1/projects` | 从项目列表移除目录 |
| `GET /api/v1/events` | 全局 SSE |

客户端共用一条 SSE 连接，按 `sessionId` 分发事件。SSE 使用 `id: <revision>` 与
`Last-Event-ID`；历史游标过期时发送 `reset_required`，客户端读取新 snapshot 后继续订阅。
慢客户端断开自己的订阅，Agent 执行不等待网络消费者。

Go 服务直接提供 HTTP，HTTPS 可由前置代理终止。桌面和移动端的远程连接支持 HTTP 与 HTTPS。

## 数据读取与同步改造

本节记录改造目标和验收规则；上面的端点表描述当前协议。新增能力应在生产调用链及对应宿主
接入完成后更新协议说明，不能把规划当成已实现能力。性能基线和复测方法见
[测试与兼容性验证](testing.md#数据读取性能验证)。

### 范围与事实依据

现有 Catalog 已缓存会话摘要，SSE 已支持游标回放，前端已有事件刷新合并和媒体延迟读取。
改造复用这些能力，解决重复构建、读取和传输完整投影，以及不同资源缺少统一版本与失效规则的问题。
小集合整体缓存、首次读取和无法验证缓存时的重建仍是合法路径；是否增加磁盘索引或持久化客户端
缓存，由冷读、热读与内存测量决定。

JSONL 和 SessionManager 的条目视图是历史依据，Agent 拥有生成中的状态。完整历史展示沿指定
分支遍历原始条目；模型上下文继续使用原版 compaction-aware 投影。旧条目不会因为压缩、
切分支或编辑并重发而失去浏览能力。会话费用统计保留完整条目日志的口径，不能按可见页面重算。

### 资源与读取边界

| 资源 | 查询与同步规则 |
|---|---|
| 会话目录 | 按项目、过滤条件和稳定排序分页，按会话更新摘要；运行中会话和总数独立提供 |
| 历史正文 | 首次读取最近一页，向前翻页或直接定位节点；条目与 entryId 同项返回 |
| 节点索引 | 与正文分页独立，支持搜索、定位、分支和编辑；保留核心规定的完整候选范围 |
| 模型上下文 | 核心按原版语义使用完整上下文，界面分页不能影响模型输入 |
| 当前运行态 | 快照包含当前生成内容、工具进度、队列与重试状态，随后按变化同步 |
| 会话统计 | 独立查询；累计用量覆盖完整日志，上下文占用按当前上下文计算 |
| 模型、工具、命令 | 按全局、项目或会话作用域缓存，依赖变化时失效 |
| 图片、thinking、大段工具输出 | 通过条目和内容块引用按需读取；不静默截断原始内容 |
| 工作目录 | 小项目集合整体缓存，目录按层展开；单层过大时分页或搜索 |

SessionManager 提供条目、分支和上下文查询，Application 提供传输无关的资源版本与同步边界。
Surface 只编码协议和维护展示缓存。普通历史读取不应顺带构建整棵树、完整模型上下文和无关配置。

### 身份、版本与一致性

- 数据源身份、sessionId、entryId 共同定位条目；不同会话中的同名 entryId 不混用。
- 会话数据代次区分追加与文件替换、截断、同 ID 内容替换。无法确认同一代次时重新校验。
- 目录、条目日志、当前分支视图、运行态和配置分别拥有资源版本；token 更新不使旧历史失效。
- 事件游标包含流代次和序号，分页游标包含查询身份、分支或目录索引锚点以及读取位置。
- 同一资源的数据与版本在同一一致性边界取得。跨资源可以返回版本组合，不伪装成全局原子快照。
- 快照期间的变化必须可回放；重叠事件按资源版本和条目身份幂等应用。补丁基础版本不匹配时
  校验对应资源，过时请求不能覆盖当前视图。
- 运行消息与提交后 entryId 的关联由负责提交的核心层提供，不按正文、时间戳或数组位置猜测。

保留原版事件顺序和持久化边界。`message_end` 不等同于条目提交；条目进入 SessionManager
视图也不一定意味着已落盘。同步不能提前强制写盘，失败操作则按实际产生的条目和 leaf 变化同步。

### 分页与缓存

历史页固定数据代次和分支锚点。正常追加只补尾部；切分支重组当前路径，共享祖先条目继续复用。
接近已加载范围顶部时读取旧页，节点和搜索结果通过附近读取直接定位，不必下载中间所有页面。
页同时控制条目数和字节量，超大内容通过引用或分块完整提供。轮次分组保留工具调用与结果关联，
不要求整个超长轮次一次下载。长历史还需要有界渲染窗口。

会话列表分页绑定短期保留的目录索引版本，避免活动时间变化导致重复或遗漏；实时变更按 ID
合并，索引版本过期时重建当前列表窗口。小集合无需强制分页。

共享 UI 数据层跨会话切换保留条目、页面范围、摘要、运行内容和配置。缓存规则为：

| 状态 | 行为 |
|---|---|
| 版本有效且范围已加载 | 直接复用，不请求 |
| 版本有效但范围未加载 | 只补该页面或内容块 |
| 收到可应用的完整变更 | 更新缓存，不重新读取 |
| 失效通知或版本缺口 | 校验对应资源，补增量或读取有界快照 |
| 数据代次变化 | 校验或失效该会话相关缓存 |
| 请求失败 | 保留最后成功数据并标记待恢复，不能当成空数据 |

同一查询合并并发请求；淘汰按字节预算管理。编辑草稿和滚动位置独立于正文页面，分页回收不丢稿。
服务端索引可以重建，不能为了缓存长期占用不需要的 Runtime 或写锁。HTTP 条件读取和 IPC 的
未变化结果使用同一资源版本。跨客户端重启的持久缓存属于后续测量决定的能力。

### 运行中会话与恢复

运行中会话分别维护已提交历史、尚未提交的生成内容和可变运行态。已有历史和已收到的生成内容
可以保留，新增 delta/patch 按版本应用；条目提交后按核心提供的身份关联归入历史，避免重复。

| 恢复情形 | 行为 |
|---|---|
| 首次访问无缓存 | 有界基础快照加同步起点，再应用读取期间的变化 |
| 短暂断线且游标可回放 | 补事件，不重读有效历史 |
| 事件过期 | 校验订阅资源，补变化摘要、历史尾部和运行态 |
| 离线期间新增历史很多 | 最新窗口加未加载范围，旧内容按需分页 |
| 服务重启 | 新流代次，重新验证资源，不沿用旧运行态 |
| 文件或数据源替换 | 重建受影响资源 |

缓存与恢复游标一致推进，不能只保存游标。全局订阅提供摘要和活动状态，详细生成内容按需订阅；
切换订阅范围时校验新增资源。保留完整核心事件能力，紧凑展示投影不得改变核心可观察语义。
回放缓冲受条数和字节预算限制，长期恢复依靠历史与当前状态。

### 失效矩阵

| 变化 | 更新范围 | 可复用范围 |
|---|---|---|
| token 或工具进度 | 当前生成内容与相关运行态 | 旧历史、其他会话、配置 |
| 新条目 | 条目、相关节点、摘要、上下文与统计 | 旧条目及固定锚点历史页 |
| 运行结束 | 最终运行态与未同步的实际变化 | 已同步历史和无关会话 |
| 改名或标签 | 对应元数据、索引及新增记录 | 历史正文 |
| 模型、thinking、工具或 reload | 相关配置、运行态及实际新增记录 | 旧正文 |
| 压缩 | 检查点、模型上下文、相关用量和状态 | 压缩前历史 |
| 切分支 | 选中路径、leaf、上下文和视图版本 | 原分支、其他分支和共同祖先 |
| 编辑历史并重发 | 新路径、新条目、生成内容和相关摘要 | 原节点、原后续路径和共同祖先 |
| fork 到新会话 | 新会话、目录和生命周期 | 原会话历史 |
| 添加或隐藏项目 | 对应项目和分组关系 | 无关会话与历史 |
| 外部文件变化 | 对应目录、内容或会话资源 | 已验证无关的数据 |
| 删除或内容替换 | 移除标记或数据代次 | 其他会话 |

编辑历史用户节点生成新分支和新 entryId，不能原地覆盖旧缓存。前置校验失败恢复原 leaf；
运行开始后失败可能已经产生新条目。旧分页响应不能混入新路径，压缩前节点也能定位和编辑，
新路径不继承旧路径中已不属于它的摘要。图片引用保持所属会话、条目和内容块的身份。

本进程事件不覆盖外部文件修改。已知写入直接更新投影，外部变更通过监测、合并校验和必要的
兜底扫描发现；不以无法验证的无限缓存替代正确性。

### 实施顺序与架构检查点

1. 固定大规模数据与场景，测冷读、热读、变化后的读取、传输字节、分配和内存。
2. 补齐资源版本、一致快照、条目变化和运行消息身份关联；先验证并发时不漏、不重复。
3. 拆分有界历史、节点、运行态和摘要查询，建立可复用的只读索引。
4. 实现资源同步、流代次、缺口修复和局部恢复。
5. 接入共享客户端缓存、分页、节点定位、分支和编辑草稿；各宿主消费相同契约。
6. 收敛命令响应和事件触发的刷新，接入目录、项目和配置的局部失效。
7. 根据复测选择流式载荷、索引与持久缓存优化；收益很小且复杂度不相称的方案不实施。
8. 完成跨端、race、兼容 fixture 和完整场景验收，更新当前协议说明。

保持契约的明确热点优化可以在上述阶段内先做，但必须有前后测量，不能替代未完成的同步能力。
需要改变核心状态所有权、原版事件或持久化语义，或只能新增第二套权威状态才能推进时，停止相关
实现，提供代码依据、失败场景、候选方案与取舍，与用户确认后再继续。

## 模块与装配

根 Go module 的 `cmd/pi-go` 装配 CLI、TUI、RPC 和 Web 服务。浏览器宿主位于
`surface/web/_frontend`：开发时 Next HMR 代理自动重载的 Go API，生产构建将静态资源
内嵌到 Go 二进制，运行时不依赖 Node。

`surface/gui` 是独立 Go module 和桌面 composition root，链接 Go Core、Wails bridge 与
Workbench 静态资源。根模块的检查与构建不遍历 GUI 模块。

`surface/mobile` 是独立 Go module，宿主包含 Android WebView 和 Go 网络桥接，不链接 Agent Core。

统一命令见[构建与发布](RELEASING.md)，平台工具链与开发步骤见
[Web](../surface/web/_frontend/README.md)、[GUI](gui.md)和[Android](mobile.md)。
